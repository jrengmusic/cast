## Context

ARCHITECT: *"i want to release binary only on cast github repo, so i could easily install on any machine"*. The source of each repo stays public. jam is private (`gh repo view jrengmusic/jam` → PRIVATE), so no CI build: each release binary comes from a local run of `cast cast/spell.md` (*"what i actually need to do is run cast cast/spell.md in the following machine (this mac universal, windows x64, and windows arm64)"*). Today the Release chain signs, notarizes and installs on mac only (`cast/cmake.cast:202-237`); no project uploads to GitHub; Windows has no sign or installer step.

Outcome: one `cast cast/spell.md` run on each of the three hosts builds, signs, packs an installer, installs locally, and uploads its installer to the GitHub Release `v<versionString>`; the first host creates the release, the others append.

## Design

### Asset name and location (D5, D6)
- The archive is `${CMAKE_SOURCE_DIR}/${CAST_PACK_folder}/<productName> v${PROJECT_VERSION} ${CAST_PACK_platform}.${CAST_PACK_format}`, following END `cmake.cast:429`.
- `## pack`, per project, follows END `project-info.md:123-133`:

| name | mac | win | description |
|---|---|---|---|
| folder | ../Release | ../Release | Archive folder |
| format | pkg | exe | Archive format |
| platform | macOS | Windows | Platform word in the archive name |

- On WIN32 the platform word gets a space and `string(TOLOWER ${CMAKE_CXX_COMPILER_ARCHITECTURE_ID})` appended, giving `Windows x64` or `Windows arm64`.
- Resulting names: `cast v0.1.0 macOS.pkg`, `cast v0.1.0 Windows x64.exe`, `cast v0.1.0 Windows arm64.exe`.

### mac lane (D12)
The existing chain is strip, xattr, codesign, verify, pkg-staging, pkgbuild (component `${PROJECT_NAME}.pkg`). A new `productbuild` fence follows it:

`productbuild --distribution cast/installer/mac/distribution.xml --package-path ${CMAKE_BINARY_DIR} --resources <resource directory> unsigned.pkg`

After it, `productsign` writes `CAST_PACK_ARCHIVE`, and `notarize`, `staple` and `qa-copy` act on `CAST_PACK_ARCHIVE` (jfs `cmake.cast:591-601`). The local install copy is unchanged.

`distribution.xml` is a new `distribution` fence, adapted from jfs `installer.cast:1-36` for one component:
- `title`
- `license file="LICENSE"`, in projects that have a LICENSE (cast, whatdbg and ggwp do; stamp does not)
- `background` and `background-darkAqua`: `file`, `mime-type="image/png"`, `alignment="bottomleft"` (jfs), `scaling="proportional"`
- `domains` with `enable_localSystem` (jfs)
- `options customize="never" hostArchitectures="x86_64,arm64"`
- `os-version min=:::deploymentTarget:::`
- one `choice` and one `pkg-ref` keyed `:::bundleIdentifier:::`

### Windows lane (D3, D4, D12, D13)
In `if(CMAKE_BUILD_TYPE STREQUAL "Release")`, `elseif(WIN32 AND CAST_SIGN)` runs:
- signtool discovery, verbatim from jfs `cmake.cast:614-619`;
- `makensis /DARTEFACT=<exe> /DOUTFILE=<archive> /DRESOURCES=<resource directory> /DLICENSE=<root LICENSE> /DSIGNTOOL=<path> cast/installer/win/installer.nsi` (jfs `:621-632`).

`installer.nsi` is a new `installer` fence, adapted from jfs `installer.cast:113-263`:
- `RequestExecutionLevel user`; `InstallDir ":::installDirectoryWindows:::"`, from a `## cmake` row `installDirectoryWindows`. The name is the existing column of archetype/plugin `## plugin format` and jfs `project-info.md:184`. Its value is `$PROFILE\.local\bin` in the four CLIs (D4); END's value is the one open question below.
- Pages: `MUI_PAGE_WELCOME`, `MUI_PAGE_LICENSE` (projects with a LICENSE), `MUI_PAGE_INSTFILES`, `MUI_PAGE_FINISH`; for uninstall, `MUI_UNPAGE_CONFIRM` and `MUI_UNPAGE_INSTFILES`. This mirrors the Installer.app panes.
- Bitmaps: `MUI_HEADERIMAGE_BITMAP`, `MUI_WELCOMEFINISHPAGE_BITMAP`, `MUI_UNWELCOMEFINISHPAGE_BITMAP`.
- Icon (D13): the CLIs' binaries have no icon (`JUCEUtils.cmake:2183-2215`), so their `installer` fence copies carry no `MUI_ICON` and NSIS keeps its default. END's and archetype/app's copies set `MUI_ICON` and `MUI_UNICON` to `${ICON}`, passed as `/DICON=<build>/<target>_artefacts/JuceLibraryCode/icon.ico`.
- Signing (D3):
  - `!system '"${SIGNTOOL}" :::signArgumentsWindows::: "${ARTEFACT}"' = 0` signs the payload exe before `File`.
  - `!finalize` and `!uninstfinalize` sign the installer and the uninstaller (jfs `:129-132`).
- The install section copies the exe, writes the uninstaller to `$DOCUMENTS\${COMPANY}\Uninstaller` (jfs `:193-194`) and writes the HKCU Uninstall key, because the installer runs at user level.
- The user PATH gains `$PROFILE\.local\bin` by the method in **PATH** below.
- The uninstall section removes the exe, the uninstaller and the HKCU key, and leaves PATH unchanged.

### Upload lane (D5, D7)
`gh.cmake` comes from a new `gh` fence in `cast/cmake.cast`, written to the project root:
1. `set(CAST_RELEASE_VERSION :::versionString:::)`; the tag is `v${CAST_RELEASE_VERSION}`.
2. The `pack-value` items, reused for `CAST_PACK_folder`.
3. `file(GLOB CAST_RELEASE_ASSETS "${CMAKE_CURRENT_LIST_DIR}/${CAST_PACK_folder}/:::productName::: v${CAST_RELEASE_VERSION} *")`.
4. `message(FATAL_ERROR)` when the list is empty: the precondition is asserted once, here.
5. `gh release view <tag> --repo :::repository:::` sets `RESULT_VARIABLE`. When it is 0, run `gh release upload <tag> <assets> --repo … --clobber`. Otherwise run `gh release create <tag> <assets> --repo … --title <tag> --notes-file "${CMAKE_CURRENT_LIST_DIR}/RELEASE.md"`. Both use `COMMAND_ERROR_IS_FATAL ANY`.

`## cmake` gains the row `repository | jrengmusic/<name>`. `## toolchain` gains a default-flow row after ninja, `| | cmake | -P gh.cmake |`.

### RELEASE.md (D8)
A new `[no-banner]release` fence in `cast/installer.cast` writes `RELEASE.md` at the project root:

- `## What's New`, from the `## release notes` table (`| note |`) through the item fence `note`
- `## Platforms` (macOS universal .pkg; Windows x64 .exe; Windows arm64 .exe)
- `## Installation`, one paragraph per platform, worded per project's install path

### PATH
Use the EnVar plugin: `EnVar::SetHKCU`, then `EnVar::AddValue "Path" "$INSTDIR"`, then `Pop` the result code. The two alternatives fail:
- **Stock NSIS.** `ReadRegStr` reads into a 1024-character buffer. On a longer PATH it returns empty and sets the error flag (`exec.c:1323-1352`), so a following `WriteRegStr` would replace the whole user PATH.
- **PowerShell `[Environment]`.** It returns the expanded value and writes REG_SZ (`Environment.Windows.cs:411-457`, RegistryKey docs), which turns REG_EXPAND_SZ into REG_SZ.

EnVar reads the registry natively with no length limit (`envar.c:332-346`), keeps REG_EXPAND_SZ (`:459`), broadcasts WM_SETTINGCHANGE (`:279`), and returns success when the path is already present (readme). It is zlib-licensed.

### Host prerequisites (ARCHITECT, per Windows host)

- EnVar `Plugins/x86-unicode/EnVar.dll`, extracted into the NSIS `Plugins/x86-unicode`. The installer stub is x86-unicode (stock 3.11 ships only `x86-*` plugin folders).
- `gh` logged in as `jrengmusic`, with scope `repo`.
- An MSVC shell from `vcvarsall x64` or `vcvarsall arm64` matching the host.

## BLESSED Alignment
- **S (SSOT):** the version is `versionString`; the asset name pattern is in one archive variable plus the `gh` glob, both fed by `productName` and `## pack`; the icon comes from the binary (none).
- **E (Explicit):** an empty asset list stops with `FATAL_ERROR`; no bail-out guards.
- **D:** the architecture comes from the compiler ID, not the host.
- **L:** `gh` has one branch; each fence does one job.
- **B:** the archive is owned by the project's build; the release is owned by the repo.
