## Where we are right now

Phase 2 is complete and beyond: the project-root `CMakeLists.txt` is the sole build
manifest, generated by CAST from data, and the **entire lifecycle is data-driven**:

- `cast cast/CAST.md` (no flag) runs the default flow declared in
  `project-info.md`'s `## toolchain` table: configure + build Release, then
  POST_BUILD strip → codesign → zip → notarize (Accepted) → atomic install to
  `~/.local/bin`. Proven end-to-end repeatedly; installed binary carries a valid
  Developer ID signature (`codesign -dv`: runtime flag set).
- `cast cast/CAST.md --debug` runs the debug flow rows (Debug configure+build, no
  signing — POST_BUILD is Release-gated). Unknown `--word` → fatal
  `toolchain argument not declared`.
- POST_BUILD commands are tokenized template fences in `cast/cmake.cast`
  (`strip`, `codesign`, `zip`, `notarize`, `install-directory`, `install-copy`,
  `install-rename`); every parameter (identity, entitlements, notary profile,
  install dir) is a visible cell in `project-info.md` (`## signing`, `## cmake`).
  Composition/order = wrapper bindings in `cast/CAST.md`'s CMakeLists wiring row.
- **`build.sh` and `install.sh` are deleted** — no scripts; the generated
  CMakeLists owns sign→notarize→install, plugin-style.
- `CAST_USER_MODULE_PATH` is gone; `@user-module` in `project-info.md`'s `## index`
  is the single per-framework path knob.

### Resolved since the last handoff

- **Scope-shape RFC (`jam/RFC-macro-scope-shape.md`) — superseded and delivered** as
  the `macro-guard` wrapper fence in `jam/cast/code.cast`: named-token wrapper,
  same-macro members collapse into one `#if … #endif` region. `jam_Generated.h`'s
  `colourId` and the `ColourIdMap` concern generate correctly guarded under
  `JUCE_MODULE_AVAILABLE_juce_gui_basics`.
- **`jam_markdown` hb dependency** — re-keyed to `#if __has_include (<hb.h>)` with
  ASCII fallback (`jam_markdown.h:18`, `jam_MarkdownDocument.cpp:489+`).
- **CMake description-newline warning** — fixed: `## cmake` `description` is a
  single line (`Codegen Annotated Source of Truth`); the multi-line banner is its
  own `banner` row printed via `message(STATUS ":::banner:::")`. Configure log is
  warning-free.
- **Reserved `## index comment` table eliminated** — file headers now come from each
  manifest's `## headers` (`file | comment`) table via a wired whole-cell address in
  the output row's comment cell. Engine laws: address-valued comment cells are
  references, never prose; a file never lists itself (self-exclusion extended to
  table sources).

- **Phase 4, redefined (ARCHITECT ruling 2026-09-01): `build-debug.sh` is obsolete
  for cast-managed projects.** Everything the script does is now data:
  - configure flags (generator, scheme, arch, `-DCMAKE_EXPORT_COMPILE_COMMANDS=ON`)
    → `## toolchain` configure-row flag cells
  - build → direct `ninja | -C Builds/<Scheme>` rows (cast's own table already
    converted; `ninja -j N` is a flag cell if a job cap is ever wanted — ninja's
    default auto-scales to cores, replacing the script's RAM formula)
  - target/format selection → per-flow rows naming each project's own targets
    (no ninja-targets grep needed)
  - notarize toggle → flows without signing rows
  - debug get-task-allow re-sign → a post-build fence + Debug-flow row, same
    pattern as codesign
  - cmake-TUI workarounds → moot; cast runs tools through ChildProcess pipes,
    no TTY to detect
  MACHINIST wires nvim to run `cast cast/CAST.md --debug` (or the project's
  declared flow word) per project as each migrates; `build-debug.sh` stays only
  for not-yet-migrated JAM/KANJUT projects and is deleted when Phase 5 completes.
  Per-scheme build directories are declared in each project's `## toolchain`
  flag cells (cast uses `Builds/Release` / `Builds/Debug`).
