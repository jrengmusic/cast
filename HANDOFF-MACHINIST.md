## Where we are right now

Phase 2 is complete and beyond: the project-root `CMakeLists.txt` is the sole build
manifest, generated by CAST from data, and the **entire lifecycle is data-driven**:

- `cast cast/CAST.md` (no flag) runs the default flow declared in
  `project-info.md`'s `## toolchain` table: configure + build Release, then the
  `post-build` custom target runs postinstall → strip → xattr → codesign →
  verify → pkg-staging → pkgbuild → productsign → notarize (`.pkg`, Accepted) →
  staple → qa-directory → qa-copy, followed unconditionally by
  install-directory → install-copy → install-rename → clangd. Proven
  end-to-end repeatedly; installed binary carries a valid Developer ID
  signature (`codesign -dv`: runtime flag set).
- `cast cast/CAST.md --debug` runs the debug flow rows (Debug configure+build, no
  signing — the sign chain is Release-and-`CAST_SIGN`-gated). Unknown `--word` →
  fatal `toolchain argument not declared`.
- Every fence above is a tokenized template in `cast/cmake.cast`
  (`postinstall`, `strip`, `xattr`, `codesign`, `verify`, `pkg-staging`,
  `pkgbuild`, `productsign`, `notarize`, `staple`, `qa-directory`, `qa-copy`,
  `install-directory`, `install-copy`, `install-rename`, `clangd`); every
  parameter (identity, entitlements, notary profile, install dir) is a visible
  cell in `project-info.md` (`## signing`, `## cmake`). Composition/order =
  wrapper bindings in `cast/CAST.md`'s CMakeLists wiring row (`## output`).
- **`build.sh` and `install.sh` are deleted** — no scripts; the generated
  CMakeLists owns sign→notarize→install, plugin-style.
- `CAST_USER_MODULE_PATH` is gone; `@user-module` in `project-info.md`'s `## index`
  is the single per-framework path knob.

### Phase 3 (eve) — DELIVERED

`eve` now runs the same full data-driven lifecycle as `cast` itself, sourced entirely
from `project-info.md` + `cast/cmake.cast`:

- Two-table build schema (`## release`/`## debug`) plus a six-row `## toolchain` table
  (default/debug/no-sign) — same argument-dispatch shape as `cast`'s own toolchain.
- An always-run `post-build` custom target solves the POST_BUILD relink-skip problem
  (old PluginBuilder `POST_BUILD` invocation was a silent no-op — Ninja skips
  `POST_BUILD` commands on a target that's already up to date; the custom target
  always runs).
- Install is unconditional on every flow (default, debug, no-sign) — no signing-gated
  branch.
- The Release chain is xattr→codesign→verify→zip→notarize→staple per plugin format.
- `wraptool` AAX signing is live: first real run succeeded end-to-end — signed,
  notarized, stapled, autoinstalled.
- A QA archive lands at `___builds___/{date} EVE v0.1.0 macOS`, with a byte-identical
  QA-vs-installed proof (the archived copy and the installed copy are the same
  bytes).
- `.clangd` regenerates on every build for both the project root and the JAM root
  (`JAM_ROOT` now passed through) — the old PluginBuilder `POST_BUILD` invocation for
  this was a silent no-op for the same relink-skip reason above.

**cast console chain** — the pkg pipeline is delivered:
`pkgbuild` → `productsign` (Installer identity) → notarize the `.pkg` → staple → QA
archive. A notarized, stapled `cast.pkg` lands in `___builds___`, and the signed
binary installs to `~/.local/bin`.

**jam changes landed this sprint:**
- `jam_Subprocess` byte-semantic rewrite — fixed a heap-bleed and a byte-cap unit bug,
  now backed by `std::string`/`std::string_view` + `jam::Array` buffers.
- `ColourId` relocated to a centralized, unguarded `generated/jam_ColourIds.h`,
  included by `jam_style` — topology is `juce_gui_basics` < `jam_markdown` <
  `jam_style` < `jam_gui` (acyclic).
- `jam_Generated.h`'s umbrella is now selector-binding driven (`- list: generated`,
  SPEC §6.2/§6.5).

**cast ripple:** headless `cast` now carries `juce_gui_basics` (an unconditional
`jam_markdown` widget dependency).

**Still open/known:**
